= Introduction and Goals

== Requirements Overview

Conference Example is a conference management system. Speakers (hundreds), organizers (dozens), and attendees (thousands) use it to organize and manage conferences in the German-speaking region.

The key features are:

* *Conference program*: Attendees see the conference program online. The program shows times and rooms.
* *Talk management*: Speakers submit and edit their talks.
* *Talk rating*: Attendees rate how popular a talk is (thumbs up or thumbs down).
* *Real-time notifications*: Organizers tell attendees about changes to the conference program in real time. Attendees must opt in.
* *Conference branding*: Each conference can have its own branding.
* *Slide sharing*: Attendees get the presentation slides online.
* *Mobile app*: A mobile conference app for attendees is planned for the future.

The main purpose of this project is to be a complete example system for presentations and workshops. The topics are Domain-Driven Design, Clean Architecture, software architecture, architecture documentation, architecture tests, and testing.

=== Additional Context

* Conferences take place in the German-speaking region.
* Only a few support staff are available.
* Very high traffic is expected during a conference.

== Quality Goals

[cols="1,2,4",options="header"]
|===
| Priority | Quality Goal | Motivation

| 1
| Understandability
| Talks and workshops use the codebase. An audience that sees the code for the first time must understand the concepts immediately.

| 2
| Testability
| The system shows different test strategies (unit tests, acceptance tests, and architecture tests). You must be able to test each layer alone with minimal setup.

| 3
| Maintainability
| The project changes with new talk topics. It must be easy to add new features or to show new patterns. Existing examples must not break.
|===

== Stakeholders

|===
| Role | Name | Expectations

| Conference Organizer
| (fictional)
| Creates and publishes conferences. Manages rooms and schedules. Reviews the submitted talk proposals.

| Speaker
| (fictional)
| Registers and browses the published conferences. Submits talk proposals with a title, an abstract, and tags.

| Conference Attendee
| (fictional)
| Sees the conference program with times and rooms. Rates talks (thumbs up or thumbs down). Gets real-time notifications about program changes (opt-in). Gets the presentation slides.

| Presenter / Author
| Andreas Lausen
| Needs a realistic, well-structured example project. The project must work in different talks. The author must be able to extend it step by step to show new architecture concepts.

| Talk Audience
| (various)
| Expects clean and readable code that shows the presented concepts. The code must not be too simple and must not be too complex.
|===
