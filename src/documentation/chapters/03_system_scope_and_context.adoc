= System Scope and Context

== Business Context

The Conference Management System has three main user roles and one external system.

[plantuml, business-context, png]
....
@startuml
skinparam actorStyle awesome

actor "Organizer" as org
actor "Speaker" as spk
actor "Attendee" as att

rectangle "Conference Management System" as sys

org --> sys : create & manage\nconferences, rooms,\nschedules
spk --> sys : submit & edit talks,\nupload slides
att --> sys : view program, rate talks,\nreceive notifications,\naccess slides

sys --> [Identity Provider] : authentication &\nauthorization

@enduml
....

[cols="1,2",options="header"]
|===
| Actor / System | Interaction

| Organizer
| Creates conferences and sets them up (rooms, time slots). Puts accepted talks in the program. Starts notifications to attendees about program changes.

| Speaker
| Submits and edits talk proposals (title, abstract, tags). Uploads the presentation slides for accepted talks.

| Attendee
| Sees the conference program (times, rooms). Rates talks (thumbs up or thumbs down). Opts in to get real-time notifications about program changes. Gets the presentation slides.

| Identity Provider
| External system for authentication and role-based authorization. The Conference Management System gives all identity tasks to this provider. It uses the tokens and claims of the provider through an anti-corruption layer.
|===

== Technical Context

The system is a *modular monolith*. It is one ASP.NET Core application. The application contains all bounded contexts as in-process modules. Each module has its own database schema in a shared database instance.
