=== Contained Building Blocks

[cols="1,1,2",options="header"]
|===
| Bounded Context | Type | Responsibility

| Conference
| Core
| Manages conferences, rooms, time slots, and the conference program. Schedules talks in slots. Refers to talks by ID only.

| Talk
| Core
| Manages talks, speakers, abstracts, and tags. Talks have their own lifecycle (submit, review, accept). The lifecycle does not depend on the conference program.

| Voting
| Supporting
| Handles the ratings of talks by attendees (thumbs up or thumbs down). It is designed for high throughput and independent scaling.

| Notification
| Supporting
| Sends real-time notifications to attendees about changes to the conference program. It is event-driven and asynchronous. It follows the opt-in preferences of the attendee.

| Attendee
| Supporting
| Manages attendee registration, profiles, and preferences (for example, the notification opt-in).

| Content
| Supporting
| Handles the upload and distribution of presentation slides. Speakers upload slides for their talks.

| Identity Provider
| Generic (external)
| Authentication and role management. It is not a custom bounded context. A standard identity product does this task. Other contexts connect to it through an anti-corruption layer. The layer changes tokens and claims into domain-specific roles.
|===

=== Important Interfaces

Bounded contexts communicate through defined interfaces. The system uses these integration patterns:

* *ID references*: A context refers to entities of other contexts by ID only (for example, `TalkId` or `AttendeeId`). Contexts do not share domain models.
* *Domain events*: The Notification context subscribes to domain events of the Conference context (for example, `ProgramChanged`). These events start the notifications to attendees.
* *Anti-corruption layer (ACL)*: A context that connects to the external identity provider changes the external claims into internal roles and permissions.
